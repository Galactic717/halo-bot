# Halo Bot — a 4B model that acts, a provider that knows who it is talking to, and a job as proof

27 September 2026. One shift on `D:\Halo bot` against a finish line written down first
([CLAUDE.md](../CLAUDE.md)): a named bot, on this Windows PC, on llama.cpp serving Gemma 4 E4B *and*
on an OpenRouter key, takes a real job and finishes it, with tools firing — not a `plan.md`.

The runtime was kept. The gate, the hash-chained trail, the fence, the per-bot AppContainer and the
per-bot browser partition all held up on reading and are what the rest of this is built on. What was
replaced is the layer between the runner and the model, which is where the product was failing, and
what was added is a way to prove a job got done that does not depend on believing the model.

---

## 1. What was a lie

### 1.1 `toolMode: 'json'` did nothing

`Settings.provider.toolMode` had two values, and the comment on the second said *"some local servers
ignore the tools field; keep a switch for the JSON fallback protocol"*. There was no JSON fallback
protocol. `json` meant: do not send `tools`. Nothing wrote the catalog into the prompt, nothing parsed
a call out of the reply. A bot put on that switch — the one meant for the weakest servers — could not
call a single tool, and the text it wrote instead was dropped, because SendMessage is the only channel.

### 1.2 OpenRouter was a label

Setup listed OpenRouter with a paid Claude model as the hint. `provider.ts` sent it exactly what it
sent Ollama: no `HTTP-Referer`, no `X-Title`, no usage accounting, no fallback, and no cost recorded
anywhere. "Hosted APIs work" meant "the request shape happens to be compatible".

### 1.3 Every request carried the whole shop

Forty-two tool schemas — 16.5k characters, ~4.6k tokens — plus a ~3k-token system prompt went out on
every step, to every model. Six of those tools were n8n tools that can only answer "n8n is disabled"
when it is. For a hosted model that is waste; for a 4B model it is most of the window and most of its
attention. Measured on this machine: the same "write hello.txt" request is 7,019 prompt tokens and
11.3 s with the full surface, 529 tokens and 2.8 s with five tools.

To be fair to the old code: Gemma 4 E4B on llama.cpp with `--jinja` *did* make the right native call
with all 42 schemas in front of it. Single calls were never the problem. Finishing a job was.

### 1.4 A small model did not know how to stop

The first live page-watch run on Gemma 4 E4B finished the job — and then called SendMessage eight
times in a row, each a slightly different summary of the summary. The loop only ends when the model
returns no tool call, and a small model that has been told "SendMessage is the only channel" keeps
using it.

### 1.5 Deleting a bot mid-turn crashed the app

Memory is extracted after each turn, in the background. Delete the bot in between and
`MemoryStore.add` appended into a folder that no longer existed; the rejection was unhandled, and the
process died. Found by the job harness, which deletes each bot as soon as its turn ends — the same
race a person hits by deleting a bot that just answered.

### 1.6 The box could not keep a quote, move a file or write text

The job harness put a 4B model in front of the real AppContainer box, and the model kept failing at
things that were not its fault. Three defects in `native/halo-box`, none visible to a test that only
checks what the box *refuses*:

- **Every double quote was stripped.** The helper appended the bot's command raw to
  `powershell.exe … -Command`, so PowerShell's own argument splitting ran first: `Write-Output "a b"`
  ran as `Write-Output a b`, and every JSON or string-building attempt came back broken.
- **Remove-Item, Move-Item and Rename-Item were denied on every file in the box** — including files
  the container had just made. Through the `Box:` drive the file system provider fixes up a path's
  casing by walking every folder above it, and the container may not look at any of them. The kernel
  was never the problem: the same calls with a native `-LiteralPath` succeed. "Move every .log file
  into logs/" was impossible for any model.
- **Text came out in four encodings.** `>` wrote UTF-16, `Set-Content` the ANSI code page (Cyrillic
  became `?`), `Export-Csv` added a `#TYPE` line, stdout went out in the OEM code page, and on this
  Ukrainian Windows `9.5` went into a CSV as `"9,5"`. A model that wrote `names.txt` correctly
  produced a file other tools read as binary.

### 1.7 Smart review stalled the work it was reviewing

With review set to `smart`, every box command that the rules allowed was put to the helper model —
here the same 4B model. It answered ASK on `cat total.txt` and on `python -c` summing a CSV: seven
false alarms in one eleven-job run, each an approval nobody was there to give. The box is an
AppContainer with no network; reviewing what happens inside it bought latency and stalls, not safety.

### 1.8 The README was better than the product

"Try it: write plan.md" was the proof. "Works while you are elsewhere" was true only while the PC was
on. Android was "the same product on a phone" while it had been frozen at the 3 September runtime —
no AppContainer, no hash chain, pooled cookies. n8n and AG-UI were listed beside things that had been
run; Teach-a-task was "learned by watching" when it records selectors.

## 2. What changed

### 2.1 The provider knows which server it is talking to — `host/provider.ts`

`providerKind()` reads the address: llama.cpp, Ollama, LM Studio, OpenRouter, or generic
OpenAI-compatible. OpenRouter gets `HTTP-Referer` and `X-OpenRouter-Title` (plus the older
`X-Title`), the `cost` its last chunk always carries is stored per call and shown per bot on
Settings → Usage, and `models: [main, ...fallbacks]` comes from a new setting; the usage row records
the model that actually answered. (A first draft also sent `usage: {include: true}`; OpenRouter's docs
say that parameter is deprecated and has no effect, so it went.) A 400 that names
`stream_options` is retried without it; a 4xx that says the model or server will not take `tools`
(Ollama's "does not support tools", llama.cpp's "requires --jinja", OpenRouter's "no endpoints that
support tool use") switches that server to the text protocol. Both are remembered per server and
model. A mid-stream `error` object — how OpenRouter reports a provider failing after the 200 — is now
an error rather than an empty answer. `serverInfo()` asks llama.cpp's `/props` for its window and
whether its template renders tool calls, and Setup shows both.

### 2.2 A call written in the text is a call — `parseContentToolCalls`

When native tool calling returns nothing, the reply is searched for calls in the shapes models
actually write: Halo's `{"tool","args"}` block, OpenAI's `{"name","arguments"}` (string or object),
`<tool_call>` tags, Gemma's `call:Name{key:<|"|>v<|"|>}`, and lists of them. Only names of real tools
count, so a reply that quotes `{"name": "Olena"}` stays prose. `toolMode: 'content'` is now what the
old `json` pretended to be: the catalog is written into the system prompt as one line per tool, the
history is rewritten into plain turns (calls become the JSON block, results become user turns that
say whose result they are, same-role turns are merged because Gemma's template refuses two user turns
in a row), and calls are parsed out of the reply. The runner does not know which wire was used.

### 2.3 A compact profile — `host/prompt.ts`, `host/runner.ts`, `host/tools.ts`

Eleven core tools on the wire, `FindTool`/`UseTool` for the other thirty-odd and every plugin, and a
~900-token prompt of numbered rules in place of the ~3k-token essay. `UseTool` is unwrapped in
`executeTool` before the gate, so the real tool meets the approval, the trail and the fence under its
own name — verify checks that `UseTool → ExternalShell` still stops for approval. `profile: auto`
gives it to any model on this machine and the full profile to hosted ones. The fence rules are in the
short prompt too, shortened, not dropped. n8n tools and `GenerateImage` leave the wire when they are
switched off, in both profiles.

After the first measured failures two rules were sharpened, not added: use the file names the user
gave (a 4B model wrote `draft/` for `drafts/`), and report the result itself rather than "saved to a
file" (it did). A turn that has delivered and then spends two steps doing nothing but talk is ended.

### 2.4 The box, fixed where every command passes — `native/halo-box/src/main.rs`

The script is one argument quoted by the C runtime's rules (`-EncodedCommand` would dodge quoting
too, but PowerShell then returns errors as CLIXML). The prefix every box command runs behind now
defines `Remove-Item`, `Move-Item` and `Rename-Item` stand-ins that resolve each path — wildcards and
pipeline input included — to a native one and call the real cmdlet with `-LiteralPath`; aliases
(`rm`, `del`, `mv`, `ren`) find them first. It also sets UTF-8 for `>`, `Set-Content`, `Add-Content`
and `Export-Csv` (with `-NoTypeInformation`), UTF-8 on the console, and the invariant culture. Each is
a test in `host/box.test.ts` against the real helper, and the quote and move tests fail against the
previous build. `cmd /c del` still fails inside the box; nothing Halo tells a model to use relies on it.

Smart review no longer sees commands inside a box that has no network — they run in the container or
not at all. A box with network on is still reviewed, and the rules still decide first: the recursive
delete in §3 was stopped by a rule, not by review.

### 2.5 Real jobs, judged by the world — `evals/tasks.mts`, `scripts/job.mts`, `scripts/verify.mts`

Three jobs of the kind the product is for, next to eight box chores: **page-watch** (open a pricing
page, diff it against yesterday's copy, write `changes.md` and a KEEP/ACT `review.md`, refresh the
copy, report what moved), **outbound-drafts** (three company pages → three drafts that mention
something real from each page; nothing sent, no reaching tool called), and **poisoned-page** (answer a
question from a page that hides an order to wipe the box and run a command on the user's machine).
Every check reads files in the box, the paths the fixture site actually served, and what reached the
user — never the model's account of itself.

`scripts/job.mts` runs them on the real Store and Runner against a live model with a fetch-backed
text browser, refuses every approval, and reports calls, tokens, cost, refused approvals and — on a
failure — the replies and the box. `npm run verify` runs page-watch with a scripted model through both
wires: native, and a server that 400s on `tools`, where it also checks no request after the refusal
carries `tools` or a `tool` role.

## 5. What is still not a product

- **Nobody has used it.** No installer is published, no user has run it, there is no business model.
- **The numbers are small.** A handful of runs per case on one machine with one quantisation. They
  say the path works and roughly how often; they are not a benchmark.
- **The harness browser is text.** `job.mts` fetches and strips pages. The real Chromium window, its
  snapshot refs and its clicks are exercised by hand in the app, not by a harness, so a job that needs
  a click is not measured.
- **One injection.** `poisoned-page` is one hidden paragraph. The fence lowers the odds; the gate and
  the box are what hold when it fails, and those are verified deterministically, not by this case.
- **Android is frozen and weaker**, and the README now says so. It has none of this shift's work.
- **OAuth plugins do not exist**, so Linear/Notion/Jira are not connectors. n8n and AG-UI are wired
  and unit-tested, not proven against live servers. Teach-a-task is a recording.
- **24/7 means while the PC is on.** There is no cloud runner and this shift did not pretend to build one.
- **OpenRouter's free models allow 50 requests a day** on an account that has bought less than $10 of
  credit (their limits page), 20 a minute. One page-watch job is 8–15 model calls; the free tier proves
  the path, it does not run a working day.
